# 模型评估 — 需求文档

**版本** v1 · **状态** 需求已定稿，待实施
**被测对象** Qwen3-VL-8B-Instruct 的 SFT checkpoint（对比 base）
**承载项目** `liugenzzz/eval_hk`（在其上扩展，不新建项目）
**数据来源** 本项目 `output/test.jsonl`

---

## 0. 这次评的是什么

评的是**训练出来的 checkpoint**，不是数据集。要回答三个问题：

1. SFT 之后，指代定位的能力**涨了多少**（对比 base）；
2. 涨的这部分**是不是靠牺牲别的能力换来的**（灾难性遗忘）；
3. 哪一档、哪一类、哪种尺寸的目标**还不行**（指导下一轮补数据）。

**第 3 点是这次评估的真正产出。** 只出一个总分没有用。全文所有设计都服务于「能拆开看」。

## 2. 任务分组与打分方式

14 个任务按**答案形态**归为五组。分组决定用哪个打分器，不决定报表怎么拆。

| 组 | 任务 | 引擎 | 主指标 |
|---|---|---|---|
| **A 单框** | `ground_unique` + 7 个 `ground_*` 的第 1 轮 | **代码** | 四点偏差 |
| **B 多框** | `detect_class`、`inventory_locate` | **代码** | 匹配后四点偏差 + 数量 |
| **C 短答案** | `attribute_qa`、`spatial_relation` | 代码 + 裁判兜底 | Acc |
| **D 自由描述** | 主线第 2 轮（7 种 describe kind） | **裁判** + 代码前置 | 分维度评分 |
| **E 物体识别** | `region_identify` | **代码**（含上下位判定） | 精确命中 / 上位命中 |

**拒答**（`exist_negative`）单独成表，见 §5。

## 3. 坐标指标 —— 四点偏差

### 3.1 在归一化空间算，不在像素空间算

偏差一律在 **[0, 1000] 归一化空间**计算。像素空间下，2048 宽的图上差 20px 和 128 宽的图上差 20px 完全不是一回事，混在一起平均没有意义。归一化空间天然可比，也正好是模型的输出空间。

### 3.2 三个层次都要报

| 指标 | 定义 | 用途 |
|---|---|---|
| `MAE_4pt` | 四个坐标各自的绝对偏差再平均 | 一个数看总体 |
| `MAE_x1` `MAE_y1` `MAE_x2` `MAE_y2` | 四个点分开 | 左边界准右边界不准 → 模型没框住目标尾部 |
| `bias_x1` … `bias_y2` | **有符号**均值（`pred − gt`） | **最有诊断价值** |

`bias_*` 的读法：

- 四个点符号一致 → 整体偏移
- `bias_x1 > 0` 且 `bias_x2 < 0` → **系统性框小**
- 反过来 → 系统性框大

绝对偏差看不出方向，看不出方向就不知道该补什么数据。

### 3.3 门槛通过率与副指标

- `Acc@dev≤20` / `Acc@dev≤50` —— 四个点的偏差**全部**不超过 N 个归一化单位（20 ≈ 图宽的 2%）
- 副指标：`Acc@IoU0.5`、`Acc@IoU0.75`、`mIoU` —— 用于和 RefCOCO 系列的公开数字横向比

### 3.4 【关键】偏差只在定位成功的样本上算

模型框到隔壁一辆车，四点偏差可能是 300。把它算进平均值会把整体拉成噪声。

**规则：`IoU ≥ 0.5` 的样本算偏差；`IoU < 0.5` 记为「定位失败」单独计数。**

报表必须同时出两个数：

```
定位成功率            = |IoU≥0.5| / N
成功样本上的四点偏差   = MAE_4pt over {IoU≥0.5}
```

只报后者会漂亮得离谱，只报前者又丢了精度信息。**两个数分开报，不许合成一个。**

### 3.5 解析退化情形（必须有单测）

真实模型输出里都会出现，一个都不能崩：

- 空输出 / 非 JSON
- 坐标顺序颠倒（`x2 < x1`）→ 规范化后再算，并计入 `malformed` 计数
- 越界（`< 0` 或 `≥ 1000`）→ 裁剪后再算，并计数
- 多包一层 ` ```json ` 围栏 → 剥离后解析，并计数（我们数据 `wrap_json_in_code_block: false`，模型不该自己加）
- 多框任务返回的框数与 gt 不等
- 重复框（同一个目标输出两次）

**坐标反归一化只能有一个实现。** 公式对齐本项目 `core/coords.py`，重复实现两遍必然对不上。

## 4. B 组多框：先配对再算偏差

1. 用 IoU 作代价矩阵做**匈牙利匹配**，阈值 0.5
2. 配上的算四点偏差（口径同 §3）
3. 配不上的分两类：**漏检**（gt 有 pred 没有）/ **误检**（pred 有 gt 没有）

指标：`P / R / F1@0.5` + **数量准确率** + **数量 MAE**。

**数量为什么要两个数**：准确率只说「多少张图数对了」，MAE 说「数错时错多少」。错 1 个是边界目标的判断，错 10 个是模型压根没在数 —— 完全不同的问题。（口径借 TallyQA。）

> **禁止项：不做 COCO 的 `AP@[.5:.95]`。**
> AP 需要每个框带置信度来排序，我们的模型输出纯 JSON 坐标，没有 score。硬上 `pycocotools` 只能给所有框填 1.0，算出来的 AP 是 F1 的一个变形，还多一层解释成本。

## 5. 幻觉与拒答

### 5.1 `exist_negative` 单独成表

我们的负样本是**易混类别**的 hard negative（图里有卡车，问有没有货车），相当于 POPE 的 Adversarial 档，难度远高于 Random 档。**不要拿 POPE 的公开数字横向比。**

报：拒答准确率、**yes 偏置率**（模型有多倾向于说「有」）。SFT 之后 yes 偏置变高是常见退化。

### 5.2 描述里的类别幻觉（CHAIR 口径）

D 组描述文本里提到的类别名，有多少不在这张图的真值类别集合里。纯代码算，有 `classes.yaml` 就够。

报 `CHAIR_i`（实例级）和 `CHAIR_s`（句子级）两个粒度。

## 6. E 组物体识别：上下位关系必须区分

金标「遮阳三轮车」，模型答「三轮车」—— 算对还是错？

用本项目 `core/classes.py` 已有的 `hypernym` 表（当初为 `exist_negative` 避开上下位词而建）做三档判定：

| 判定 | 条件 | 计入 |
|---|---|---|
| **精确命中** | 归一化后完全一致 | 主指标 |
| **上位命中** | 答案是金标的上位词 | **单独计数** |
| **错误** | 其余 | — |

**主指标报精确命中率，上位命中率作为第二个数，不许合成。** 合成会掩盖一个真实问题：模型可能学会了「答粗一点更安全」，那是退化不是能力。

答案不在类别表里（模型自创了词）才丢给裁判判一次是不是同义 —— 这是 C/E 组唯一用到裁判的地方。

## 7. 多轮：一次推理出两个数

### 7.1 三次前向，不是四次

```
第 1 轮：问「框出 X」          → B_pred          ← A 组指标在这里算
第 2 轮 gold ：历史塞 B_gt      → D_gold
第 2 轮 model：历史塞 B_pred    → D_model
```

第 1 轮只跑一次，两种历史共用。`D_model` 只对 **30% 抽样子集**跑 —— 链路衰减率是统计量，不需要全量。

### 7.2 链路衰减率

```
链路衰减率 = (D_gold 得分 − D_model 得分) / D_gold 得分
```

这是「专项训练该补哪边」的直接依据：

| 现象 | 结论 |
|---|---|
| 衰减大 | 瓶颈在**定位** —— 框错了描述再好也白搭，补定位数据 |
| 衰减小但 `D_gold` 本身低 | 瓶颈在**描述** —— 补描述数据 |
| 两个都高 | 这一轮 SFT 成了 |

> `eval_hk` 目前只支持 gold 回放（`convert_vqa_json.py` 把历史轮的标准答案塞进 history 列）。`history_mode: model` 是新增能力。

## 8. D 组描述：代码判 + 裁判判，分工写死

### 8.1 四条维度，三条给裁判一条给代码

| 维度 | 引擎 | 说明 |
|---|---|---|
| **正确性** | 裁判 | 说的内容图里有吗（幻觉） |
| **落地性** | 裁判 | 说的是不是**这个框里**的东西，而不是图里别处的 |
| **信息量** | 裁判 | 是不是「一辆车」这种空话 |
| **范围合规** | **代码** | `appearance` 有没有跑去说方位、`position` 有没有跑去说外观 |

**范围合规必须走代码**，直接复用本项目 `prompts/describe/*.txt` 里的 `#! must-not:` 词表。理由：通用的「描述准确性」rubric 会给跑题答案高分（说得没错啊），裁判判不出「跑题」这件事。代码判更准、更省钱、可复现。

### 8.2 按 describe kind 拆开报

7 种 kind 的答案信息结构完全不同，合成一个平均分等于把这次数据集设计的核心抹掉。**报表必须有 7 行。**

## 9. 格式合规与指令跟随

微调模型特有的失败模式，公开评测集不会覆盖：

| 指标 | 定义 |
|---|---|
| **坐标格式合规率** | 能否解析成 `bbox_2d`、是否越界、是否自作主张加了 ` ```json ` 围栏 |
| **任务串味率** | 问框答文字、问描述吐坐标 |
| **截断率** | 撞上 `max_new_tokens` 的比例 |

这三个降到接近 0 是 SFT 最先体现的效果，涨得最快，也最能早期发现训练配置有问题。

> **对比 base 时的陷阱**：Qwen3-VL base 会自己加 ` ```json ` 围栏，如果解析器不宽容，base 的 `Acc` 会因**格式**而虚低，报表会好看得离谱 —— 那测的是格式差异不是能力差异。
> **要求：解析器对两种格式一视同仁，围栏只计数不扣分。**

## 10. 附加评估（本轮采纳两项）

### 10.1 双向一致性（借 Ferret 的 Referring ↔ Grounding 对偶）✅ 采纳

```
正向：问「框出白色面包车」   → 框 B
反向：拿 B 问「这个框里是什么」 → 类别 X'
X' 和「白色面包车」对得上吗？
```

**不需要任何额外标注** —— 我们的数据集同时有 `ground_*`（文字→框）和 `region_identify`（框→文字）。

它测的是模型有没有真的建立**文字 ↔ 区域的双向映射**，还是只单向背下了「看到『框出』就吐坐标」。判定复用 §6 的上下位三档。

报 `双向一致率`。这是整套评估里信息量最高的单个指标。

### 10.2 问法扰动鲁棒性 ✅ 采纳

同一个目标，用问法池里 **3 种不同说法**问，答案框应该一样。

报三次输出之间的**四点偏差方差**和 **IoU 一致率**（两两 IoU ≥ 0.9 视为一致）。

这测的是对问法的过拟合。SFT 数据的问法有限，模型很容易学成「看到某个固定句式才输出坐标」，换个说法就崩 —— 这个失败模式在真实使用中极常见，而标准评测集完全测不出来（它们的问法也是固定的）。我们有现成的问法池，生成扰动零成本。

抽 300 条 A 组样本做。

### 10.3 POPE random 档对照 ⛔ 本轮不做

（记录备查：补一档随机负样本，与 adversarial 档的差值可反映模型是在看图还是在用语言先验猜。本轮未采纳。）

## 11. 评估集抽样

### 11.1 分层原则

**主分层维度只有 `task_type`。** 难度档、尺寸档、类别、describe kind 都是**事后拆分**（post-hoc），不参与抽样保量。

理由：2000 条 ÷（14 任务 × 3 难度档 = 42 格）每格不到 50 条，`n=50` 时二元指标最坏情况下 95% CI 半宽是 **±13.9pp** —— 每一格都得标灰，做完全交叉分层等于白做。

### 11.2 配额（合计 2000）

| 组 | 任务 | 条数 |
|---|---|---|
| **A / D 主线** | `ground_unique` | 260 |
| | `ground_appearance` | 160 |
| | `ground_full` | 140 |
| | `ground_state` | 120 |
| | `ground_position` | 120 |
| | `ground_relation` | 120 |
| | `ground_part` | 120 |
| | `ground_contrast` | 100 |
| | *小计* | *1140* |
| **B 多框** | `inventory_locate` | 200 |
| | `detect_class` | 160 |
| **E 识别** | `region_identify` | 160 |
| **拒答** | `exist_negative` | 160 |
| **C 短答案** | `attribute_qa` | 100 |
| | `spatial_relation` | 80 |
| **合计** | | **2000** |

A 组和 D 组**共用同一批样本**（主线的两轮），D 组不额外占配额。

### 11.3 难度分布：评估集不必等于训练集

训练集 hard 占 10%（`difficulty.hard_quota`）。**评估集把 hard 提到每个任务内 ≥ 25%。**

这不是偏差，是有意为之：训练集控制 hard 比例是为了不让模型被难样本带偏；评估集提高 hard 比例是为了把那一档看清楚。

**前提条件（必须遵守）**：三档分开报，**不做跨档加权汇总**。要出一个总分时，按训练集的真实分布加权回去，并在报表上注明。

### 11.4 统计功效与标灰规则

| n | 最坏 95% CI 半宽 |
|---|---|
| 50 | ±13.9pp |
| 100 | ±9.8pp |
| 160 | ±7.7pp |
| 260 | ±6.1pp |

- **`task_type` 级**（n = 80~260）：可下结论
- **`task_type` × `difficulty` 交叉**（n = 25~65）：**只看趋势，一律标灰，不下结论**
- **难度档结论只在组级别汇总时给**（A 组整体的 easy / medium / hard，n 数百）
- 任何 **n < 30** 的格子：报表显示 `n=xx（样本不足）`，不显示百分比

### 11.5 【设计上为空的格子】

`ground_part` 和 `ground_contrast` 的提示词带 `#! max-grade: medium`，**设计上就不会有 hard 档样本**（困难目标看不清部件、也分不出和同类的差别，硬写就是编）。

**这两格的 hard 列是空的，标注为「设计上为空」，不是「数据不足」。** 实现的人看到空格会当 bug 修，必须在报表里写明。

## 12. 评估集冻结

checkpoint 数量待定（看训练效果决定评几个）。正因为不定，**评估集必须冻结**，否则不同时间评的 checkpoint 之间没有可比性。

抽样一次后固化为 `eval_set_v1.jsonl`，记 `sha256`。每份评估报告必须记录四个指纹：

```
eval_set_sha      评估集内容哈希
profile_version   打分口径版本
rubric_version    裁判提示词版本
judge_model       裁判模型标识
```

**报表层硬校验：四者任一不同的结果，不许画进同一张对比图。** `eval_hk` 已有 inference fingerprint 机制（README 明确写了指纹变化时报错而不是静默重跑），把它扩展到评估集即可。

## 13. 评估模式（profile）

### 13.1 核心约束

> **profile 只回答一个问题：这种 kind 的数据，用哪个打分器、哪版提示词。**

数据的 `kind` 从数据集配置来。换一套数据不用改 profile，换一套口径不用改数据。这样评通用问答时切到 `general_vqa` profile 全走裁判，完全不受这套确定性打分器影响。

### 13.2 配置形态

```json
"profile": {
  "name": "grounding_zh_v1",
  "scorers": {
    "grounding_single": { "engine": "code", "impl": "bbox_deviation",
                          "params": { "iou_gate": 0.5, "dev_thresholds": [20, 50] } },
    "grounding_multi":  { "engine": "code", "impl": "bbox_match_hungarian",
                          "params": { "iou_gate": 0.5 } },
    "object_ident":     { "engine": "code", "impl": "class_name_match",
                          "params": { "hypernym_table": "classes.yaml" },
                          "fallback": { "engine": "judge", "prompt": "judge_synonym_v1.txt" } },
    "short_answer":     { "engine": "code", "impl": "normalized_exact",
                          "fallback": { "engine": "judge", "prompt": "judge_synonym_v1.txt" } },
    "describe":         { "engine": "judge", "prompt": "judge_describe_v1.txt",
                          "dims": ["correct", "grounded", "informative"],
                          "code_precheck": "describe_scope_v1" },
    "exist_negative":   { "engine": "code", "impl": "yes_no_match" }
  },
  "pairwise": ["describe"],
  "history_modes": ["gold", "model"],
  "model_history_sample_ratio": 0.3
}
```

### 13.3 三条硬约束（验收标准）

1. **profile 不描述数据是什么，只描述怎么打分。**
2. **`engine: "code"` 的打分器不许调任何模型。** 一行网络请求都不能有。同一份预测重跑一百遍，A / B / C / E 组的数字必须**逐位相同**。要有测试守着。
3. **提示词全部外置、带版本号，profile 里按文件名引用。** 沿用 `eval_hk` 现有的 `prompts/judge_*_v1..v4b` 命名习惯。

### 13.4 pairwise 范围

**只有 D 组做 pairwise**（base vs sft，含位置互换）。A / B / C / E 组有确定答案，pointwise 的绝对分就够了，pairwise 纯属浪费裁判调用。

## 14. 裁判可信度

### 14.1 不做人工锚点

**决定：不做。** 人工标 100~200 条的锚点本身可能偏，成本高且不可靠，反而会给出一个虚假的「绝对正确率」。

### 14.2 已知局限：裁判池只有 Qwen 家族

裁判是 Qwen3.8-27B，被测是 Qwen3-VL-8B，**同家族**。同家族裁判可能偏爱同家族的输出风格。

**当前无法做自偏检测**（没有异家族裁判）。这一条必须写进每份评估报告的「已知局限」章节，不许省略。

### 14.3 替代方案：三重交叉验证

拿不到「正确性」，就把能拿到的「稳定性」和「与代码指标的一致性」做扎实：

| 手段 | 做法 | 读法 |
|---|---|---|
| **rubric 版本间一致性** | 同一批 300 条用两版 rubric 打分，报 Spearman + 平均绝对差 | 一致率低 → rubric 有歧义，**先改提示词再看分数**，否则是在解读噪声 |
| **位置互换一致性** | pairwise 正反各判一次（`eval_hk` 已实现） | 正反结论不一致的比例即位置偏置 |
| **代码指标交叉验证** | D 组的**范围合规率、CHAIR 幻觉率、空话率**与裁判分数**并列报** | 两者走向不一致 → **裁判有问题**，以代码指标为准 |

第三条是最重要的一条：这三个代码指标**完全不受裁判偏置影响**，是 D 组唯一的客观锚。

### 14.4 D 组结论的使用限制

**D 组分数只能做纵向对比**（base vs sft，同一套裁判、同一版 rubric、同一个 eval_set_sha），**不能当绝对值对外报**。

这个限制写进报告，不是缺陷说明，是没有人工锚时的正确姿态。

## 15. 对比与回归

### 15.1 必跑 base

`eval_hk` 的 `baseline_model` 机制现成。注意 §9 的格式陷阱。

### 15.2 配对 bootstrap

`eval_tool/aggregate.py:10` 的 `bootstrap_binary_ci` 是**非配对**的。两个模型跑在**同一批样本**上，配对重采样的置信区间会窄得多，更容易看出小幅提升是不是真的。

**新增两项：**

- `bootstrap_paired_diff_ci()` —— 对同一样本的差值重采样
- 连续量版本 —— `summarize_binary_metric` 只接受 0/1（`metric_col="hit"`），四点偏差和 IoU 是连续值

### 15.3 通用能力不退化

拿 `eval_hk` 现成的 `aero_mcq` / `aero_vqa` 再跑一遍 base vs sft，不显著掉即可。几乎零成本 —— 工具本来就是干这个的。

## 17. 对 `eval_hk` 的结构性改动要求

### 17.1 【前置重构】打分器注册表

**这一项必须先做，否则后面全是补丁。**

现状：

```python
# eval_tool/run_eval.py:62
for dataset_key in ("mcq", "judge", "vqa"):
# eval_tool/run_eval.py:98
    if dataset_key in {"mcq", "judge"}:
```

`config.py:239` 的 `datasets` 是自由键名，但打分逻辑写死了这三个。不动它，新增的 grounding 会变成第四个 `elif`，接着多框、短答案、物体识别再各塞一个，`run_eval` 会变成六分支的巨型函数。

**要求：数据集配置里声明 `kind`，打分器按 kind 查注册表分派。**

`kind` 取值：`choice` / `judge_text` / `grounding_single` / `grounding_multi` / `short_answer` / `object_ident` / `describe` / `exist_negative`

**验收标准：这是纯重构，现有 40 多个测试文件应当一条断言都不用改就能通过。重构提交里如果改了现有测试的断言，说明重构改变了行为，打回。**

### 17.2 新增打分器的单测覆盖

IoU / 偏差打分器必须覆盖 §3.5 列的全部退化情形。这些在真实模型输出里都会出现。

### 17.3 坐标反归一化只有一个实现

公式对齐本项目 `core/coords.py`。

### 17.4 像素预算硬校验

`infer` 块的 `image_min_pixels` / `image_max_pixels` **必须与训练时的 LLaMAFactory 配置一致**（`eval_hk` README 已写明是 65536 / 589824）。

分辨率变了，坐标虽是归一化的不会错位，但模型的空间精度会变，测出来的数字不可比。

**要求：配置加载时硬校验，不一致直接报错。不许只写在文档里。**
